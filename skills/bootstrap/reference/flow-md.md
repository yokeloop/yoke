# .yoke/flow.md — the declarative flow map

Format contract for `.yoke/flow.md`: the per-project flow map that declares the
linked repos, each repo's finish policy, the branch cascade, deploy/release
commands, the tracker, and the local-only choice for `.yoke/` itself.

## What it is

- **Hand-editable markdown**, not JSON. Parsers tolerate hand edits; humans own
  the file.
- **Committed by default** — it is a team artifact, so every teammate's agent
  behaves the same way.
- **Generated by bootstrap**, refined during grill sessions, and read by
  `do`, `merge`, `gca`, `gp`, and `pr` instead of re-asking the user.
- Lives at `.yoke/flow.md`. One per project.

## Sections

Each section is optional. Omit what the project does not need — omission means
"apply the default", never "fail".

### Repos

List every linked repo as a bullet with three fields:

- **role** — `app` or `library`.
- **path** — checkout path (repository root, or `.` for the current repo).
- **finish policy** — `pr` or `direct-push`.

`pr` finishes by branch → push → pull request (the default). `direct-push`
finishes by committing to the repo's default branch, then **publishing the
package and bumping its version in the consumer repos**. A `direct-push` repo
therefore adds two fields:

- **publish** — the shell command that publishes the package (e.g. `npm publish`).
- **consumers** — the repos whose dependency version `do` bumps after publish.

### Branch cascade

An ordered chain of branches (e.g. `master → staging → develop`) plus **how each
step is executed** — the command `merge` runs to advance one branch to the next
after the task's PR lands. Absent means no cascade: the finish target is the
single default branch.

### Deploy / release commands

Explicit shell commands. `merge` runs them **only when declared here** — never
inferred. Each command may name the repo and stage it belongs to.

### Tracker

The ticket system — `github`, `youtrack`, or `none` — and the **target state**
`merge` moves the task's ticket to on finish. `do` posts a PR-link comment to the
same tracker. With `none`, both steps are silently skipped.

### Artifacts

The local-only choice for `.yoke/` itself: `committed` (default) or
`local-only` (adds `.yoke/` to `.gitignore`). Recorded here so every skill
respects it without re-asking. Either way, no skill writes artifacts outside
`.yoke/`.

## Graceful absence

Skills must **never fail or nag** when `.yoke/flow.md`, or any field in it, is
missing. A missing file or field degrades to its default:

| Missing          | Behaves as                                                                                                |
| ---------------- | --------------------------------------------------------------------------------------------------------- |
| The whole file   | Single repo (current checkout), `pr` finish, no cascade, no deploy, no tracker steps, committed artifacts |
| Repos section    | Single repo — the current checkout, role `app`, finish `pr`                                               |
| Finish policy    | `pr`                                                                                                      |
| Branch cascade   | No cascade — finish on the single default branch                                                          |
| Deploy / release | No commands run                                                                                           |
| Tracker          | No ticket comment, no ticket transition                                                                   |
| Artifacts        | `committed`                                                                                               |

## Fields

| Field                | Values                              | Default          | Consumed by           |
| -------------------- | ----------------------------------- | ---------------- | --------------------- |
| repo role            | `app` \| `library`                  | `app`            | `do`                  |
| repo path            | checkout path                       | current checkout | `do`, `merge`         |
| finish policy        | `pr` \| `direct-push`               | `pr`             | `do`                  |
| publish (library)    | shell command                       | —                | `do`                  |
| consumers (library)  | repo names                          | —                | `do`                  |
| branch cascade       | ordered branch chain + step command | none             | `merge`               |
| deploy / release     | shell commands                      | none             | `merge`               |
| tracker              | `github` \| `youtrack` \| `none`    | `none`           | `do`, `merge`         |
| tracker target state | state name                          | —                | `merge`               |
| artifacts            | `committed` \| `local-only`         | `committed`      | bootstrap, all skills |

## Examples

### Single repo

```md
# Flow

## Repos

- **web** — role: app, path: ., finish: pr

## Tracker

github, target state: Closed

## Artifacts

committed
```

### Multi-repo: app + npm library

App finishes via PR; the ui-kit library finishes via direct push to `master`,
`npm publish`, and a version bump in the app. YouTrack tracker, `master → staging`
cascade.

```md
# Flow

## Repos

- **app** — role: app, path: ~/organization/velvetnet/app, finish: pr
- **ui-kit** — role: library, path: ~/organization/velvetnet/ui-kit, finish: direct-push
  - publish: `npm publish`
  - consumers: app

## Branch cascade

master → staging

- Advance staging after merge to master: `git switch staging && git merge --ff-only master && git push`

## Deploy / release

- Deploy app: `ssh deploy@app 'cd /srv/app && git pull && pnpm i && pm2 restart app'`

## Tracker

youtrack, target state: Done

## Artifacts

committed
```
