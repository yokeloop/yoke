`yoke` is a Claude Code plugin. It is a marketplace of skills and slash-commands that turn a ticket into a merged change.

## The shape of the loop

Each skill owns one concrete step. The default loop is short:

1. **`/yoke:bootstrap`** — once per project: detect the stack, scaffold `.yoke/`, write `flow.md` and CLAUDE.md.
2. **`/yoke:grill`** (or **`/yoke:grill-docs`**) — stress-test the plan one question at a time into a shared understanding.
3. **`/yoke:do`** — plan, execute, and drive the run to a ready pull request. It stops there.
4. **Review the PR on GitHub** — you comment and approve; the merge decision stays yours.
5. **`/yoke:merge`** — run the post-PR tail from `flow.md`: merge, cascade, deploy/release, move the ticket, clean up worktrees.

Side-quests around the loop:

- **Spec** (for larger, trackable work): `/yoke:prd` → `/yoke:issues`, then hand a URL to `/yoke:do`.
- **Git** (standalone; `/yoke:do` folds these into its finish): `/yoke:gca`, `/yoke:gp`, `/yoke:pr`.
- **Utilities**: `/yoke:review`, `/yoke:journal`, `/yoke:handoff`, `/yoke:help`.

## Why a plugin

A Claude Code plugin is installable from a marketplace. Skills auto-activate by trigger phrases written into their description. Commands stay invokable as `/yoke:<name>`. The whole catalogue lives in one repo, ships through one `plugin.json`, and updates atomically.

## Why a workflow

Each skill produces an artifact the next skill consumes. `/yoke:prd` writes a PRD, `/yoke:issues` breaks it into sub-tasks, `/yoke:do` reads a task and writes a plan plus a report. The artifacts live in `.yoke/ai/<slug>/` — version-controlled, reviewable, replayable. The map every skill reads, `.yoke/flow.md`, is written once by `/yoke:bootstrap`.

## Distribution

`yoke` is installable from the Claude Code plugin marketplace. See the [Install](/yoke/install/) page for the exact commands.
